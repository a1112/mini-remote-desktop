## 测试 4: 瓶颈分析

### 时间分解

```
捕获占比: 88.7%  ← 主要瓶颈
显示占比: 11.2%
```

### 为什么 FPS 收敛？

不同捕获方法 (GDI/MSS/PIL) 带显示后 FPS 都在 18-20 左右，原因是：

1. **捕获时间差异被系统开销掩盖**
2. **OpenCV imshow 引入固定延迟**
3. **waitKey(1) 消息循环处理**

## 测试 5: 技术对比 (OBS vs Python)

| 特性 | OBS | Python |
|------|-----|--------|
| 捕获 API | DXGI Duplication (GPU) | GDI (CPU) |
| 编码器 | NVENC/QSV/AMF (硬件) | libx264 (软件) |
| 编码速度 | < 5ms/frame | 20-30ms/frame |
| 架构 | 多线程异步 | 单线程同步 |
| 最终性能 | **60 FPS** | **30 FPS** |

## 关键结论

1. **1080p 是最佳分辨率** - 可达 60 FPS 纯捕获
2. **GDI 是最快的捕获方法** - 比 MSS 快约 2 倍
3. **显示是主要瓶颈** - 占用约 11% 的时间
4. **异步架构有效** - 效率从 60% → 93%
5. **30 FPS 已足够** - 主流视频服务标准
