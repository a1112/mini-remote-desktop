# Android 双向远程会话设计

## 目标

小米 14 Pro 安装独立 Android 应用后，既能观看并操作 Windows 桌面，也能在用户批准屏幕采集和启用辅助功能后，让电脑观看并操作手机。桌面端通过 `mrd-service` 的移动网关提供会话入口。原有 React 响应式界面继续服务桌面和浏览器；Android 应用提供原生权限及媒体能力。

## 当前边界

桌面 Tauri 后端依赖 Windows 服务、DXGI 和本机 IPC，不能直接打包成 Android 应用。现有浏览器预览通道只有画面，浏览器 IPC 明确拒绝输入指令。移动端因此需要独立入口，不能把现有响应式页面直接装入 WebView 后宣称具备远程控制能力。

## 架构

`apps/Rdesk-Mobile` 是原生 Android 应用。它通过 WebSocket 连接 `mrd-service` 移动网关，支持控制端与被控端两种模式。服务端使用现有 Windows 桌面采集和输入注入适配器；Android 使用 `MediaProjection` 前台服务采集屏幕，使用 `AccessibilityService.dispatchGesture` 注入触控。电脑控制手机的页面由移动网关提供，并可从桌面客户端打开。

网关默认关闭，显式启用后监听配置地址。所有 WebSocket 连接要求独立的随机配对密钥。局域网直接连接只适用于受信网络；公网连接需要后续接入现有加密信令和中继层。不能在未加密的公网连接中传输配对密钥、画面或控制输入。

手机在启动后发送 UDP 局域网发现探测，并在首页列出响应的网关。响应只包含设备名称和端口，不含密钥。用户仍需输入配对密钥；广播受路由器隔离时保留手动地址入口。

## 线协议

- `/mobile/desktop/ws`：Android 控制端接收 JPEG 帧，发送归一化指针、按键和滚动事件。首个文本消息携带密钥和角色，认证前不发送帧、不执行输入。
- `/mobile/phone/publish/ws`：Android 被控端发送 JPEG 帧，接收触控、系统返回/主页和文字输入。仅用户主动启动屏幕采集后建立连接；断连立即停止采集并清除画面。
- `/mobile/phone/control/ws`：电脑接收手机 JPEG 帧，发送触控和系统操作。用户可在手机通知栏随时结束。
- 帧为二进制 JPEG；状态和输入为 JSON。尺寸信息在会话开始及旋转时发送。限制帧大小、消息大小及帧速率，满队列丢弃旧帧。

## Android 权限与用户控制

每次采集先由 `MediaProjectionManager.createScreenCaptureIntent()` 请求系统批准，再启动 `foregroundServiceType=mediaProjection` 的前台服务。辅助功能须由用户在设置中手动启用，服务仅处理当前有效会话的输入。应用主界面显示连接状态、配对地址、权限状态和停止按钮。屏幕锁定或采集撤销时关闭会话。应用不使用 ADB 授予辅助功能权限。

## 验收

1. Android APK 可在连接的小米 14 Pro 上安装、启动，且不崩溃。
2. 错误密钥无法获取画面或执行输入。
3. 手机能收到电脑真实桌面帧，触控映射到电脑坐标并可点击、滚动、输入。
4. 手机批准采集和启用辅助功能后，电脑能看到实时手机画面并执行触控与返回/主页。
5. 会话结束、断连或权限撤销时停止采集、释放输入状态；用户可在手机端随时终止。

## 限制

首个交付链路为同一受信局域网，画面使用 JPEG 以便两端通过平台 API 稳定解码。后续应迁移至现有 QUIC/WebRTC 媒体和加密 WAN 信令，以满足公网访问与高刷新率要求。
