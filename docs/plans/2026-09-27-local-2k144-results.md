# 本机 2K144 低延迟优化记录

日期：2026-09-27。承接已批准的本机零拷贝分层优化，优先降低远控延迟并保持操作流畅。目标输入为 2560×1440、144 FPS，即每帧 6.944 ms。实施计划见 `2026-09-27-local-2k144-low-latency.md`。

## 测量边界

- 请求帧率、处理吞吐、DXGI 新桌面版本、渲染器成功 Present 与显示器实际扫描输出分别记录。缓存帧和鼠标位置更新不能证明每秒产生了 144 张新桌面画面。
- 前后对照固定 H.264、80 Mbps、144 FPS、DXGI/NVENC/NVDEC/D3D11、loopback、waitable 呈现和线程优先级。共享请求与显式 CPU 两条路径分别比较；两路径的采集方式不同，不能用横向差值归因单个优化。
- app 测试程序为 debug profile，app 自身 opt-level=2，多数媒体依赖 opt-level=0。原有 harness 窗口上限 1280×800，2K 视频输入不等于 2K 呈现后缓冲，更不等于跨机器远控性能。
- 单独的 release NVENC 探针使用 GPU 清屏生成变化的纯色，共享 BGRA 输入、P1/UltraLowLatency、2560×1440/144/80 Mbps。它只隔离编码组件能力；纯色易于编码，不能代表复杂桌面画质或端到端能力。

本机硬件、驱动和 CUDA/D3D11 互操作限制见 `2026-09-27-local-zero-copy-results.md`。使用 `tests/benchmarks/scripts/prepare_local_nvidia_runtime.ps1` 准备当前进程的驱动 DLL 路径；没有修改系统驱动或持久 PATH。

## 结果

当前源码的 app 测试程序构建成功，两条基线均 exit 0。可执行文件 SHA256 为 `C50F62E8F984F558DC1A3BB2AEF1F85F5CED1B503D238F4D4B440DFF2146552C`；两个首帧码流均经独立解码确认 2560×1440。

| 指标 | 请求共享 | 显式 CPU |
|---|---:|---:|
| 解码帧数 | 1106 | 612 |
| 成功呈现帧数 | 224 | 236 |
| 解码 FPS | 142.56 | 78.54 |
| 呈现 FPS（管线运行时间口径） | 28.87 | 30.29 |
| 渲染延迟 p95 | 42.77 ms | 34.77 ms |
| 观测端到端零拷贝 | false | false |

实际客户区为 1264×761。管线时间由 capture count / capture FPS 重建，不包含组件初始化但包含最终清理；若按进程总时间计算，呈现 FPS 分别为 21.71 和 28.71。运行附近存在其他构建活动，精确重叠未采样；这些是诊断基线，不能作为受控性能提升结论。缓存采集没有独特桌面更新计数，解码约 143 FPS 不代表每秒产生或呈现了 143 张新桌面画面。

原始日志、码流、视口、源文件及依赖哈希位于本机忽略目录 `artifacts/local-zero-copy/2026-09-27/2k144-baseline/`，不提交可能包含桌面内容的原始素材。测量使用当时完整工作区，其中包括独立的 H.264 zero-reorder 配置改动；该独立改动不包含在本次限定范围的提交中。因此此基线不是提交树的独立重测。
