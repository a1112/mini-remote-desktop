# 设置界面补齐与 Windows 终端弹窗处理

日期：2026-10-09。用户已批准推荐核心设置方案，并已自行关闭残留终端窗口。

## 目标

完成 Rdesk 的可用设置界面，消除仅改变组件状态却没有实际效果的误导；清理截图中的大量终端窗口，并修复已确认的重复弹窗来源。设置在现有主窗口内打开。

## 已有事实

- 实际入口是 `Layout` 的 `SettingsModal`，`SettingsPage` 没有注册路由，两份设置实现重复。
- 主题已保存到 `app-theme`；FFmpeg 探测/下载/恢复默认已有命令。账户退出已有 `AuthContext.logout()`，设置按钮未调用。
- 语言、托盘、代理、P2P、带宽、显示、音频、通知和安全开关多数只使用组件状态；网络检测数字是常量。
- Rust `AppSettings` 目前仅保存 `decode_policy` 和 `ffmpeg`。解码 getter 返回迁移错误，setter 的保存不代表服务采用该策略。
- Windows 的服务管理和开机启动存在 IPC 权限/能力限制，界面需显示实际结果和限制。
- 打开设置会探测 FFmpeg/ffprobe；资源工作台约每 2 秒采样 NVIDIA 信息。相关后台 `Command` 缺少 Windows 隐藏创建标志，具有闪窗风险。它们是否造成截图中的长期堆叠窗口仍需进程树实证。

## 方案比较

1. 快速整理：保留 Modal、移除假数据、标明未实现功能，改动最小，但通用偏好仍不完整。
2. **推荐：补齐核心设置。** 统一设置内容，完成本地偏好持久化与窗口关闭行为、账户退出、真实服务状态、权限感知的服务操作和 FFmpeg 管理，保留其他分类并呈现实际支持状态。
3. 全部功能实现：同时新增多语言、代理、音频、通知、安全/账户和媒体默认策略后端，属于多个独立功能项目。

## 推荐界面与数据流

- 保留通用、安全、网络、显示、音频与输入、通知、账户分类，窄窗口可滚动，选中状态、键盘和读屏语义清晰。
- 设置由一个共享内容组件提供，Modal 负责展示与关闭；旧页面复用该组件或移除冗余实现。
- 通用：主题立即生效并持久化；窗口关闭行为保存为本地 UI 偏好并接入原生关闭事件。开机启动读取真实值，保存失败保留原值，显示错误和支持条件。
- 网络：展示真实服务存活/健康/PID和已有连接信息；无测量数据时展示“未测量”。启动/停止/重启仅走现有合法管理接口，显示真实失败原因。
- 显示：展示解码策略的实际支持/应用状态，避免仅保存到 shell 文件就报告生效。FFmpeg 探测、下载和恢复默认保留已有接口，防止重复点击和并发探测。
- 账户：显示当前账户，退出调用既有 logout；未支持的升级、改密和注销显示能力状态。
- 未接入后台的语言、安全、代理/P2P、媒体、音频和通知控件标明状态并禁止无效修改，不把 UI 偏好当作安全或会话授权。
- 加载、保存中、成功和失败都有明确反馈；异步结果不得在关闭后覆盖新一次打开的状态。

## 终端清理与根因修复

- 先记录终端进程名称、PID、创建时间、父进程和子进程，确认当前会话遗留且空闲的实例；不按 `cmd.exe` 名称批量终止全部进程。
- 后台调查/构建命令使用隐藏进程创建方式。若根因在执行工具的 shell 生命周期，修正本轮调用方式并清理已识别的遗留实例；不伪称修改产品解决工具问题。
- 对已确认的产品后台外部命令采用 Windows `CREATE_NO_WINDOW`，保持输出捕获、失败传播和原有进程生命周期；交互式终端不受影响。
- 只有进程树和调用链证据支持的路径进入修复范围。重复状态检查/探测避免不必要并发，不将清理当作根因修复。

## 验收

- 前端组件测试覆盖设置分类、主题、持久化、账户退出、加载/失败和真实未支持状态；不使用 mock 成功声称后台功能已实现。
- Rust 验证本地设置兼容读取和窗口行为，后台外部命令保持输出/错误语义。
- 类型检查和构建通过；打开、关闭、重复刷新设置不会持续新增控制台窗口。
- 清理前后保存进程计数和目标PID，保留用户终端及活动任务；报告未能确定归属的窗口。

批准推荐方案后编写实施计划，再实施产品行为变更。
