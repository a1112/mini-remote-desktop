# 本机网页远控性能验证与优化

用户目标：先完成本机网页连接本机正式服务的测试，随后自动测试和性能调优。用户已明确授权“自动测试，无限授权”。

## 已确认的起点

- 正式已安装服务身份与版本已核验；本机设备码为 1501515774。
- 本机时钟落后信令服务器约 2.3 秒，使正式 challenge 校验失败。启动现有 W32Time 并使用原时间源同步后，真实 challenge 测试通过，正式信令认证和临时访问就绪，服务 PID 未变。
- C 盘已满。新生成的服务增量缓存迁移并保留于 L 盘；后续构建、临时文件和性能证据使用 L 盘。
- 当前正式 Windows 采集编码使用 DXGI CPU 帧与 OpenH264；网页默认 1920x1080、30fps、10Mbps。
- 当前正式 Agent profile 上限为 120fps、100Mbps；本次保留该上限。
- 正式 WAN peer 的 RTP fps 当前取默认 60，没有绑定会话批准的 profile。
- 网页/桌面工具 kernel 初始化失败。尚无正式网页画面、输入、帧率或端到端延迟通过证据。

## 方案选择

仅调整软件编码的码率不能充分利用 RTX 5060 Ti。仅跑 NVENC 组件基准可以确认硬件能力，但不能完成正式网页验证。本次选择将已有硬件编码接入正式授权后的采集链路，保留软件回退，并提供连接前性能档位，同时修正明确存在的 RTP 配置不一致。

## 实现范围

1. Windows 正式采集适配器在每个已授权资源内优先创建低延迟 NVENC；初始化不支持时使用 OpenH264。编码保持批准的尺寸、fps、码率与 H.264 SDR。资源归属、桌面、授权、签名、私有 IPC 与关闭流程保持原有验证。
2. 网页连接前选择档位，默认保持现有 1080p30/10Mbps，提供 1080p60/20Mbps 和 1440p120/40Mbps 测试档。profile 经现有请求承诺和签名 grant 绑定；不在批准后偷偷改变参数。
3. WAN peer 的 fps 从已验证 grant 的 approved_profile 取得；无视频 profile 时保留既有默认。测试覆盖 30/60/120，验证实际 peer 参数。
4. 不扩大 IPC 帧大小，不取消原生硬件输入授权检查，不引入无限期授权机制。

## 验证与实际完成条件

- 新行为先加入可失败的回归测试；运行相应 Rust/前端测试及类型检查。
- 既有硬件编码基准作为隔离能力证据，记录分辨率、配置、输入局限、样本数、吞吐和耗时分布。
- 正式网页会话须实际观察持续画面、鼠标和记事本输入，断开后活动会话数归零。
- 同一场景预热后至少 30 秒采集 browser video total/dropped frame counters 和进程/GPU 负载；性能档逐步提高，记录结果。
- 未取得真实网页证据前，不声称 120fps 达标，不将隔离编码吞吐、配置上限或网络路由标签当作端到端结果。
